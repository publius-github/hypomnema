# Contributing to Hypomnema

Thanks for taking the time. Bug reports, small fixes and documentation improvements are the most welcome contributions; for anything larger, please open an issue first so we can agree on the approach before you spend time on it.

## Reporting

- **Bugs** - open an issue with the bug template: app version (About dialog), platform, what you did, what you expected, what happened. A minimal vault or YAML snippet that reproduces it helps more than anything else; strip anything personal first.
- **Security problems** - not in a public issue; see [SECURITY.md](SECURITY.md).
- **Feature ideas** - open an issue describing the problem it solves. The app is deliberately local-first with no server and no telemetry, so ideas that need either are unlikely to land.

## Getting set up

Requirements: Node.js 22.22.2+ or 24.15+ (`engines` in `package.json`; CI runs the version in `.nvmrc`), Rust 1.98.0 via rustup. On Windows also VS Build Tools (Desktop C++) and WebView2; on Linux (Debian/Ubuntu names) `build-essential pkg-config libwebkit2gtk-4.1-dev libappindicator3-dev librsvg2-dev patchelf` - the set CI installs. CI runs Node from `.nvmrc` and pins Rust in `.github/workflows/ci.yml`; a newer Rust stable can bring clippy lints CI does not have yet.

```bash
npm ci
npm run app:dev       # the app with hot reload, as "Hypomnema Dev"
```

Google Drive sync needs an OAuth client compiled in (see the README's *Building* section). Without one the app works fully, with sync reported unavailable - that is the normal state for a development build.

Use a throwaway vault folder while developing, never your real one. `npm run app:dev` runs the development build as a separate app (`src-tauri/tauri.dev.conf.json`: identifier `com.hypomnema.app.dev`): its per-device folder is `%APPDATA%\com.hypomnema.app.dev` - its own remembered vault path, Google sign-in, device id and log - so it starts beside an installed Hypomnema and never opens that one's vault. The two still share the global capture shortcut: whichever starts second reports it cannot register it. Plain `npm run tauri dev` is the installed app's identity (`%APPDATA%\com.hypomnema.app`) - it opens the installed app's vault, runs any new migration on it and, with the OAuth client compiled in, syncs with your Google account; avoid it on a machine where you use the app.

## Where things live

Read the maps before the sources - they are kept current and save a lot of exploring:

- [`docs/general/ARCHITECTURE.md`](docs/general/ARCHITECTURE.md) - vault layout, config schemas, engine invariants, module responsibilities.
- [`docs/general/DECISIONS.md`](docs/general/DECISIONS.md) - why things are the way they are.
- [`docs/windows/ARCHITECTURE.md`](docs/windows/ARCHITECTURE.md) and [`docs/android/`](docs/android/) - platform specifics.

The ground rules of the codebase:

- **The Rust core owns all logic** (task generation, dedup via `rule_runs`, overdue carry-over, YAML parsing, sync, watchers). The React layer is presentation only - if a change needs a decision about data, it belongs in `src-tauri/src/`.
- **Vault paths go through `src-tauri/src/vault.rs`**; never join layout paths by hand.
- **Settings over hardcode** - a count, size, horizon or toggle that could reasonably differ between users is a field in `AppConfig` (`src-tauri/src/config.rs`: default, `sanitized()` clamp, `settings_pairs()`), with its TypeScript binding regenerated by `cargo test` (ts-rs) and a control in the matching Settings tab.
- **User data is sacred** - the engine never overwrites a user's edits or statuses, and a broken config file never touches data. Any change near generation, the tasks mirror or sync needs tests that show this still holds.
- **Update the docs in the same PR** - whichever `ARCHITECTURE.md` section describes what you changed.

## Before opening a pull request

CI runs these (with `cargo fmt --check` and `npm run coverage` in place of `cargo fmt` and `npm test`), and clippy warnings are errors:

```bash
npm run lint && npm run typecheck && npm test && npm run build
npm run e2e        # first time: npx playwright install chromium
cd src-tauri && cargo fmt && cargo clippy --all-targets -- -D warnings && cargo test
```

- There is no Prettier config; keep the surrounding style by hand. `.editorconfig` sets the basics (LF, final newline, indent width) for editors that read it.
- Optional pre-commit hook for the fast part of these checks (`cargo fmt --check`, ESLint on staged files): `git config core.hooksPath .githooks`.
- Commit messages: a short summary line (about 72 characters) and, when it helps, a body explaining why.
- Added, removed or upgraded a dependency? Run `node scripts/general/third-party-licenses.mjs` and commit the regenerated `THIRD_PARTY_LICENSES.txt` (for an Android dependency, update `scripts/general/notices/android-libraries.txt` first - its header says how). CI fails when it is stale, and likewise when `src/bindings/` differs from what `cargo test` regenerates - commit those files with the Rust type change.
- **Do not bump the version** or edit `VERSION`, the manifests' versions or `CHANGELOG.md` headings - the maintainer does that when merging. A line describing your change in the PR is enough.
- Keep one topic per PR; a refactor mixed into a fix is hard to review.
- UI changes keep the accessibility checks green: `npm run lint` includes `jsx-a11y`, and `npm run e2e` runs axe-core over every screen. Everything a mouse can do needs a keyboard path (see *Accessibility* in `docs/general/ARCHITECTURE.md`).
