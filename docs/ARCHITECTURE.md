# Architecture Reference

Maintained map of the current codebase, kept accurate so a new session can build context from this file instead of re-reading the sources. Update the affected section in the same commit whenever a change touches vault layout, config schemas, engine invariants, module responsibilities, or the build/release flow. Verified against the code at v0.33.0.

## Layers

- Rust core (`src-tauri/src/`) owns all data and business logic: SQLite, YAML parsing, the generation engine, watchers, filesystem access for Journal/Notes. Exposed as ~46 `#[tauri::command]`s in `lib.rs` plus the `vault-updated` event.
- React frontend (`src/`) is presentation only: one Zustand store (`src/store.ts`) wrapping `invoke` calls, ts-rs generated types in `src/bindings/` (regenerated by `cargo test`), Tailwind tokens, CodeMirror 6 editor.

## Vault layout (`vault.rs`)

All working files live under `<vault>/.hypomnema/` (like a repo's `.git`). Never join layout paths by hand - use the helpers in `vault.rs` (`work_dir`, `config_dir`, `settings_file`, `db_path`, `tasks_dir`).

```
<vault>/
  journal/<YYYY>/<YYYY-MM-DD>.md   # journal entries
  .trash/                          # Notes deletes, pruned after 30 days
  .hypomnemaignore                 # gitignore-like filter for the Notes tree
  <user notes>                     # KB root = vault root unless config.kb_path set
  .hypomnema/
    app.db (+wal/shm)              # WAL mode, migrations in db.rs (13 entries)
    settings/app.yml               # AppConfig, source of truth; SQLite `settings` is a mirror
    config/                        # user YAML configs, seeded with commented samples
      recurring.yml scheduled.yml birthdays.yml
      weekly-focus.yml day-reminders.yml day-schedule.yml
      templates/journal.md
      <subfolder>/*.yml            # "packs": merged into recurring/scheduled/birthdays by top-level key
    tasks/                         # two-way Markdown mirror of manual tasks (tasks_mirror.rs)
    backups/db/ backups/config/    # daily VACUUM INTO + pre-rewrite config copies (backup.rs)
```

The only state outside the vault is `vault-path.txt` in the OS app-config dir. `migrate_layout` moves pre-0.32 flat vaults into `.hypomnema/` (resumable, step-by-step). All file writes go through `write_atomic` (tmp + rename).

## UI sections

Order configurable via `config.section_order`; Settings always last. Rail also has Search (Ctrl/Cmd+K), Sync (runs engine), theme toggle, About.

- **Dashboard** - day grid (`grid_columns`, paged) over list-zone backlog columns (paged, split draggable); dnd-kit drag between days/lists; weekly focus + day reminders from `dashboard_context`.
- **Upcoming** - sub-tabs Scheduled / Birthdays / Recurring; CRUD writes back into the YAML files (comment-preserving splice in `config_files.rs`).
- **Calendar** - month grid: real tasks + read-only projections from `views::calendar_outlook`, per-cadence horizons.
- **History** - month completion stats, per-rule daily streaks, completed tasks by day; bounded by retention pruning.
- **Journal** - one Markdown entry per date, template-seeded (`{{date}}`), file created on first save.
- **Notes** (section id `kb`) - file tree over the KB root, editor, content search, wiki `[[links]]`, `.trash`, plus a Config group editing the six YAMLs + journal template with save-time validation.
- **Settings** - tabs Appearance / Planner / Calendar / Navigation / Files / Maintenance (`src/sections/settings/`).

## Config files (`config_files.rs`, `config.rs`)

| File | Schema |
| --- | --- |
| `recurring.yml` | `tasks: [{schedule: cron, description, items: ["{List} text"]}]` |
| `scheduled.yml` | `events: [{date: YYYY-MM-DD, title, time?}]` |
| `birthdays.yml` | `birthdays: [{name, date: MM-DD, year?}]` |
| `weekly-focus.yml` | `rotation: cycle`, `phrases: [..]` (no packs) |
| `day-reminders.yml` | `reminders: [{day_type: workday\|weekend\|mon..sun, text}]` (no packs) |
| `day-schedule.yml` | `blocks: [{from, to, label}]` (no packs) |

Packs: subfolders of `config/` are walked recursively; a `*.yml` file contributes to whichever of the three task sections its top-level keys name. Errors carry the path relative to `config/`. Broken files never wipe state - last valid config stays active, error shows as a banner.

`AppConfig` (~60 fields): theme/typography, dashboard layout, task display (cadence colors, done display/hold), engine (`retention_days`, `catchup_days`, `cron_ignore_time`), calendar outlook horizons, `section_order`, files (`kb_path`, `tasks_mirror`, `backup_keep`), `notify_system`, markdown editor color presets. Adding a setting = field + default + `sanitized()` clamp + `settings_pairs()` in `config.rs`, ts-rs regen via `cargo test`, control in the matching Settings tab.

## Engine (`engine.rs`)

Three generators per pass: recurring (cron), scheduled events, birthdays. No separate dailies/priority generator: "daily" is a cadence bucket derived from firing frequency (`cadence_of`), priority is manual-only and reset on generated tasks every pass.

- **Dedup**: `rule_runs(rule_key, period_key)` ledger, keys via stable FNV-1a 64. Period keys: recurring `YYYY-MM-DDTHH:MM`, scheduled `YYYY-MM-DD`, birthday `<year>`. Deleted instances never regenerate (tombstones); `repair_orphaned_period` unblocks today/future periods whose task vanished without a deliberate delete.
- **Catch-up**: window `[now - catchup_days, today + grid_columns - 1]`; missed firings collapse into the single latest one (one overdue copy, not N); `MAX_FIRINGS = 2000` runaway guard; fresh rules start from today (`rule_seen`).
- **Reconcile**: removing a rule/item removes its future + today's open instances; done instances stay as history. Missing/comment-only `recurring.yml` is treated as transient (generation may run, reconcile must not).
- **Carry-over**: open pre-today tasks move to today with the overdue mark (priority included unless `priority_overdue` is off); dailies are exempt and get rehomed to their firing day; at most one open overdue copy per rule.
- **Pass phases** (one IMMEDIATE transaction): priority reset -> generate x3 -> carry-over -> retention prune -> clear done list-backlog tasks (`clear_done_list_tasks`) -> purge soft-deleted (>24h, except pending tombstones) -> trim old `rule_runs` -> dedupe errors. Returns `EngineOutcome{generated, carried_over, removed, pruned, errors}`.

## Core modules

- `tasks.rs` - lists/tasks CRUD; soft delete (`archived_at`) backs the undo toast; lists carry a `favorite` flag (sorts ahead in the list zone).
- `tasks_mirror.rs` - Markdown mirror of manual tasks only: one file per list + `scheduled.md`; per-line `^<id>` sync keys; marker first line; gated by `config.tasks_mirror`; folder watcher imports outside edits.
- `journal.rs` - entry open/save/list/search, template at `config/templates/journal.md`.
- `kb.rs` - Notes FS layer; `resolve()` blocks path traversal; `.hypomnemaignore` glob filter; trash + 30-day prune.
- `reminders.rs` - `dashboard_context`: weekly focus (ISO-week pinned via `weekly_focus_state`), day-type reminders, schedule blocks.
- `views.rs` - read-only projections: upcoming, birthdays, recurring list, calendar outlook, daily streaks, cron weekday labels.
- `backup.rs` - daily DB snapshot (`VACUUM INTO`) + pre-rewrite config backups, rotation by `backup_keep`, best effort.
- `db.rs` - migrations (13), refuses a newer-than-known `user_version`; `mirror_settings`.
- `lib.rs` - commands, `AppState`, three debounced watchers: `config/`+settings (reload + engine + `vault-updated`), `tasks/` (mirror import), KB root.

## Frontend notes

- Store invalidation: `vaultVersion` counter bumped by engine runs and `vault-updated`; sections re-fetch on it.
- `src/lib/`: date helpers, wiki-link codec, markdown lint/table, md color presets, updater flow (silent on failure, runs once on mount).
- Global keys: Ctrl/Cmd+K search, Ctrl/Cmd+1..7 sections. 60s rollover engine re-run, 30s due-task notification timer, 6s undo toast.

## Build, release, tests

- `VERSION` is the single version source; `scripts/bump.sh` syncs `package.json`/`tauri.conf.json`/`Cargo.toml`; `scripts/release.sh` = bump + commit + tag `v*` + push. PowerShell twins: `build.ps1`, `release.ps1`. `scripts/build.sh` = local `npm ci && tauri build` (signs updater artifacts only if `~/.tauri/app-pkb.key` present).
- CI (`ci.yml`, push to main + PRs): frontend lint/typecheck/test/build; rust fmt/clippy(-D warnings)/test.
- Release (`release.yml`, tag `v*`): Windows-only NSIS build via `tauri-action`, draft release; first step fails on tag/VERSION mismatch. Updater endpoint = `releases/latest/download/latest.json`; secrets `TAURI_SIGNING_PRIVATE_KEY(_PASSWORD)`.
- Tests: 94 Rust `#[test]`s inline per module (engine.rs is the biggest at 39); frontend Vitest, pure-logic only (`src/lib/*.test.ts`, `dateFields.test.ts`), no component render or e2e tests.
